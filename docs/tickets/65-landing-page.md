# #65 — Стартовая страница с описанием и входом

- Issue: https://github.com/aabramov77/running-tracker_new/issues/65
- Ветка: `Dev`
- Коммиты: `feat: #65 …`, в теле PR — `Closes #65`

## Контекст

При открытии сайта сразу всплывал Google One Tap: в `index.html` стоял
`g_id_onload` с `data-auto_select="true"`, а `app.js` включал оверлей
`#login-screen` (карточка с заголовком «Полумарафон 09.08.2026») ещё до
проверки токена. Новый посетитель не видел, что это за продукт, а вошедший
на долю секунды видел экран входа, пока шёл `/me`.

Нужно: стартовая страница в стиле спортивных порталов (Strava, Nike Run Club,
Runna) с описанием возможностей и кнопкой входа; после входа — приложение.

Что сохраняется:
- вход только через Google Identity Services, бэкенд проверяет ID-токен
  (`api.py`, `config.CLIENT_ID`) — бэкенд не меняется;
- статусы доступа `pending` / `rejected` и их экраны;
- хостинг: GitHub Pages (prod, из `main`) и Cloudflare Pages (dev, из `Dev`);
  Authorized JS origins в Google Console те же.

## Согласовано

| Вопрос | Решение |
|---|---|
| Где живёт лендинг | В том же `index.html`: секция `#landing` вместо оверлея `#login-screen`, `.app` скрыт до входа |
| Стиль | Тёмный «Ночной старт»: full-bleed hero, узкий заголовок капсом (Oswald — есть кириллица; у Bebas Neue и Barlow Condensed её нет), фирменный зелёный `#1D9E75` и осветлённый `#2BD49A` для тёмного фона, SVG-«беговая дорожка», чередование тёмных и светлых секций |
| Иллюстрации | HTML/CSS-мокапы: телефон с «Сегодня», график нагрузки, диалог ИИ-тренера с «было → стало». Без бинарных файлов |
| Вернувшийся пользователь | Тихий повторный вход One Tap; новому посетителю окно не всплывает |

Отклонённые варианты:
- **Отдельная страница** (лендинг `index.html`, приложение → `app.html`):
  лендинг легче, но редиректы для вошедших, код входа в двух местах,
  перенацеливание всех проверок `INDEX`. Промежуточный `welcome.html` с
  редиректом из `<head>` собирает недостатки обоих.
- **Светлый стиль** как в приложении — ближе к SaaS, чем к спортпорталу.
- **Фото** (Unsplash/Pexels) — вес, подбор и лицензия; PNG-скриншоты
  устаревают с каждой правкой UI.
- **Вход только кнопкой** — вернувшиеся жали бы «Войти» каждый час.

## Изменения

### Страница (`index.html`, `landing.css`)
Панель с якорями и компактной кнопкой Google → hero (заголовок, кнопка,
«доступ по заявке», телефон с «Сегодня») → полоса фактов → шесть карточек
возможностей → нагрузка (график) → ИИ-тренер (диалог и правка плана) →
тренерам → как начать в три шага и сохранность данных → финальная кнопка и
подвал. Тексты — только про то, что есть в README.

- `<title>` без захардкоженного забега, `meta description` и OG-теги для
  превью ссылки.
- Стили лендинга — отдельный `landing.css` со своими токенами `--l-*`: тёмные
  секции тёмные в любой теме, светлые следуют теме системы. Мокапы берут
  токены приложения из `style.css` и выглядят как приложение в той же теме.
  Мокапы скрыты от скринридеров (`aria-hidden`).
- Режим страницы — класс `landing-mode` на `<body>`: прячет `.app` и нижнюю
  панель, у лендинга обычная прокрутка. Брейкпоинты 900 и 600 px.
- Знак приложения — один `<symbol id="rt-mark">` на лендинг, заставку и экраны
  заявки/отказа.

### Вход (`app.js`)
- GIS переведён с HTML-API на JS-API: `initGoogleAuth()` → `initialize` +
  `renderButton` в каждый `[data-gsi-button]` по конфигу `GSI_BUTTONS`
  (`compact` — в панели, `large` — в hero и внизу). Скрипт GIS `async`,
  поэтому `initGoogleAuth` зовётся и из `window.onGoogleLibraryLoad`, и при
  запуске. `GOOGLE_CLIENT_ID` совпадает с `config.CLIENT_ID` (проверяет тест).
- **One Tap — только вернувшемуся** (`offerOneTap`): флаг
  `rt_signed_in_before` ставит `handleCredentialResponse`, снимает `signOut`.
- **Защита от входа по кругу:** если `/me` отказал не из-за истёкшего токена
  (сеть, сервер), повторный One Tap дал бы тот же отказ. Поэтому в течение
  `ONE_TAP_PAUSE_MS` (5 мин) после свежего токена One Tap не предлагается —
  остаются кнопки. Параллельные 401 дают один показ страницы и один One Tap.
- **Старт без мигания:** свежий токен (`tokenFresh` — поле `exp` с запасом
  60 с) → заставка `#splash-screen` до ответа `/me`; иначе стартовая страница.
  После входа кнопкой — тоже заставка, а не лендинг.
- `signOut` и `handleAuthError` (все 39 вызовов не тронуты) показывают
  стартовую страницу через `showLanding()`. Экраны переключаются в одном
  месте — `ACCESS_SCREENS`.

### Тесты (`tests/test_frontend_sanity.py`)
`landing.css` с cache-buster; в разметке нет `g_id_onload` /
`data-auto_select` / `#login-screen`; `prompt()` — один и только под флагом
вернувшегося и паузой после свежего токена; у каждого `[data-gsi-button]` есть
конфиг; `client_id` фронта = бэкенда; заставка до `/me`; экраны в
`ACCESS_SCREENS` существуют; якоря ведут на секции; мокапы скрыты от
скринридеров.

2. Browser pane, `python -m http.server` + подменённые `fetch` и
   `google.accounts.id.prompt`:
   - 1024 / 768 / 375 px, светлая и тёмная тема, без горизонтальной прокрутки;
     кнопки Google на `localhost` отрисовались, ошибок в консоли нет;

     приложение; `pending` / `rejected` — свои экраны; выход — лендинг, флаг
     снят, `disableAutoSelect`, без One Tap; 401 сразу после входа — без One
     Tap; 401 через час, три параллельных — ровно один One Tap; истёкший токен
     при запуске — лендинг без запросов к API.
3. Dev-стенд (Cloudflare Pages после push в `Dev`): настоящий вход через
   Google новым и вернувшимся пользователем — проверяет пользователь.
