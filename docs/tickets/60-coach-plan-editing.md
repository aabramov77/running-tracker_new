# #60 — Тренер создаёт и корректирует план спортсмена

- Issue: https://github.com/aabramov77/running-tracker_new/issues/60
- Ветка: `Dev`
- Коммиты: `feat: #60 …` / `fix: #60 …`

## Контекст

В #44 тренер получил доступ к данным спортсмена только на чтение: планы,
план/факт, журнал, плюс общий чат. Правка плана тренером была явно вынесена
«вне рамок». Тест `test_coach_routes_can_only_read_except_chat` закрепляет это:
все маршруты `/coach/athletes/…`, кроме чата, принимают только `GET`.

Теперь тренер должен сам создавать планы своим спортсменам и вести их: править
недели, карточку гонки, загружать план из CSV/JSON. Главный риск тот же, что в
#44, — граница авторизации, только теперь на запись. Поэтому право по-прежнему
проверяется в одном месте, а каждая правка тренера ложится в существующую
модель версий плана (#25), проходит ту же сверку версии (#51), что и правки
спортсмена и ИИ-тренера (#46), и оставляет след: автор, причина, сообщение
спортсмену.

Решения, согласованные до реализации:

| Вопрос | Решение |
|---|---|
| Как применяется правка | Сразу: сохранение тренера — новая версия плана. Спортсмен получает сообщение в чате, видит историю. Согласования, как у ИИ-тренера, нет |
| Согласие спортсмена | Отдельный переключатель в карточке «Мой тренер», **по умолчанию включён**. Выключен — тренер только смотрит |
| Активный план и архив | Решает спортсмен. План тренера становится активным, только если активного плана нет. Архивировать тренер не может |
| Телефон | В этой итерации тренер правит только на десктопе (как и конструктор спортсмена). Мобильная правка дня — отдельной задачей |

Допущения: переключатель относится к связи с конкретным тренером — при выборе
другого тренера он возвращается к значению по умолчанию (включён); архивные
планы тренер не видит (#44) и, значит, не правит.

## Модель данных

**Переключатель — в реестре**, рядом с `coach_sub`: это та же
авторизационная метка, что и сама связь, и проверяется она тем же чтением
реестра мимо кэша.

- `coach_plan_edit: bool` у записи спортсмена. Нет поля — значит `true`
  (значение по умолчанию; у всех текущих пар правка сразу разрешена).
- `set_user_coach` при смене тренера удаляет поле — новому тренеру действует
  значение по умолчанию.
- История — `append_user_event`: `coach_plan_edit_allow` /
  `coach_plan_edit_deny`.

**Автор версии плана.** В payload версии и в манифест добавляется
`author: {role, sub}`, где `role` — `athlete` | `coach` | `ai`. `created_by`
(email) остаётся как был — для аудита. Версии до #60 автора не имеют, роль
для истории выводится из прежних признаков: `created_by == "auto-migrate"` —
перенос, причина «ИИ-тренер: …» — `ai`, остальное — `athlete`.

**Автор плана** в реестре планов: `created_by_role`, `created_by_sub` у записи,
созданной после #60. Старые записи без полей — планы спортсмена.

**Уведомление** — обычное сообщение чата пары (#44) от роли `coach` с
дополнительными полями `kind: "plan_change"`, `plan_id`, `plan_version`.
Объект неизменяем, непрочитанные считаются как раньше — по роли в имени.

## Бэкенд

### `storage.py`

- `coach_access(bucket, coach_sub, athlete_sub)` → `None` | `"view"` |
  `"edit"`. Единственная проверка права; реестр мимо кэша, как у
  `coach_can_access`, который становится обёрткой `coach_access(...) is not None`.
  `"edit"` — связь действует и у спортсмена не выключен `coach_plan_edit`.
- `set_coach_plan_edit(bucket, sub, allow)` — по свежему реестру, только при
  действующем тренере (иначе `CoachLinkError("no_coach")`), с событием.
- `list_athletes_of` дополнительно отдаёт `can_edit` каждого спортсмена.
- `write_plan_version(..., author=None)` и `save_plan_weeks(..., author=None)`
  пишут автора в версию и манифест. `apply_ai_proposal` передаёт
  `{"role": "ai", "sub": <спортсмен>}`, ручная запись спортсмена —
  `{"role": "athlete", "sub": <спортсмен>}`.
- `create_plan(..., make_active=True, author=None)`: для тренера вызывается с
  `make_active=False` — существующее условие «активным, если активного нет»
  делает ровно то, что решено.
- `read_plan_history(bucket, sub, plan_id, limit=50)` → версии от новых к
  старым: `version`, `created_at`, `change_reason`, `author_role`,
  `author_name`. Имя — из реестра по `author.sub`; **почта не отдаётся**
  (как у `_coach_card`). Объекты версий читаются параллельно
  (`_load_json_objects`).
- `append_chat_message(..., extra=None)` — дополнительные поля сообщения
  (`kind`, `plan_id`, `plan_version`); текст по-прежнему проверяется.

### `api.py`

`_coached_athlete(c, edit=False)`: нет связи → `Forbidden` (403 `forbidden`,
одинаковый для чужого и несуществующего sub, как в #44); связь есть, но правка
выключена → новое исключение `EditNotAllowed` → 403 `edit_not_allowed`.
Различать эти два ответа безопасно: второй получает только тот, кто и так
видит спортсмена.

| Метод | Путь | Кто | Что |
|---|---|---|---|
| POST | `/coach/athletes/{sub}/plans` | тренер, edit | создать план: карточка гонки, необязательно `weeks` + `change_reason` (импорт «новым планом» одним запросом) |
| POST | `/coach/athletes/{sub}/plans/{pid}/meta` | тренер, edit | изменить карточку гонки |
| POST | `/coach/athletes/{sub}/plans/{pid}/weeks` | тренер, edit | новая версия недель; `base_version` **обязателен** (новому маршруту не с кем быть совместимым); устаревшая → `409 plan_stale` |
| GET | `/coach/athletes/{sub}/plans/{pid}/weeks?meta=1` | тренер | недели с `plan_id` и версией (общий `_plan_weeks_resp` получает sub) |
| GET | `/coach/athletes/{sub}/plans/{pid}/history` | тренер | история версий |
| GET | `/plans/{pid}/history` | спортсмен | история версий своего плана |
| POST | `/my/coach/plan-edit` `{allow: bool}` | спортсмен | переключатель; без тренера → `409 no_coach` |

- `GET /my/coach` и `/me` (поле `coach`) отдают `can_edit_plans`.
- Архивный или чужой `pid` → 404, как у просмотра.
- После успешной записи — сообщение в чат: «Тренер создал план «X»» /
  «Тренер изменил план «X»: <комментарий>» / «Тренер изменил карточку гонки
  «X»». Сообщение — best-effort: если чат не записался, план уже сохранён,
  ошибка уходит в лог, в ответе `notified: false`.
- Журнал, чат, архив, активный план, DELETE — по-прежнему недоступны тренеру
  (405 / нет маршрута).

## Фронтенд (`app.js`, `index.html`, `style.css`)

**Общий конструктор.** Из `renderPlanTable` (ветка редактирования) и
`collectPlanEdits` выделяются чистые функции — по образцу `planViewRowsHtml`
из #44, поведение у спортсмена не меняется:

- `planEditRowsHtml(weeks, {onDelete, onAdd})` — строки редактора;
- `collectPlanEditsFrom(root, weeks)` — поля обратно в массив недель;
- `newPlanWeek(n)` — пустая неделя.

**Экран спортсмена у тренера** (`tab-coach`, состояние — только в `COACH`):

- Кнопки: «+ Новый план», «✏ Гонка», «⤒ Загрузить» (CSV/JSON через
  существующие `parsePlanCSV` / `parsePlanJSON`), «✏ Редактировать»,
  «История». Если у спортсмена правка выключена — кнопки записи скрыты,
  строка «Спортсмен не разрешил править план»; «История» остаётся.
- Пустое состояние «У спортсмена пока нет плана» → «Создать план».
- Черновик правки — `COACH.draft`, версия — `COACH.base = {plan_id, version}`
  (недели грузятся с `?meta=1`).
- Панель сохранения: поле «Что изменилось (увидит спортсмен)» → причина
  версии и текст сообщения в чате.
- Импорт: предпросмотр в редакторе, «Сохранить в этот план» / «Создать новый
  план» / «Отмена».
- `409 plan_stale` → недели перечитываются, редактор остаётся открытым уже со
  свежим планом, сообщение (как в #51). `403 edit_not_allowed` → редактор
  закрывается, сообщение, кнопки скрываются. `403 forbidden` → прежний
  `coachAccessLost`.
- Несохранённый черновик при смене плана, спортсмена или уходе с экрана —
  подтверждение.
- Свои `PLAN` / `PLANS` / `ACTIVE_PLAN` / `localStorage` тренера по-прежнему
  не трогаются (`test_coach_screen_keeps_out_of_own_data`).

**У спортсмена:**

- «Мой тренер»: переключатель «Тренер может создавать и менять мои планы»
  (включён по умолчанию), сохраняется сразу; текст карточки — что тренер видит
  и что может менять.
- Сообщение `plan_change` в чате выделено и с кнопкой «Открыть план»; если
  изменён не активный план — подсказка с его названием.
- «История» на вкладке «План» — список версий: кто (вы / тренер Имя / ИИ-тренер),
  когда, причина.
- `PLAN_STALE_TEXT` упоминает и тренера.
- `index.html`: `app.js?v=45` (и `style.css?v=29`, если меняется).

## Тесты

- `tests/test_registry.py`: переключатель по умолчанию включён; выключение и
  включение пишут события; сброс к умолчанию при смене тренера; без тренера →
  `no_coach`; `coach_access` — матрица `None` / `view` / `edit`.
- `tests/test_routes.py`:
  - новые пути разрешаются в свои хендлеры;
  - матрица изоляции на **каждом** маршруте записи: не тренер, чужой тренер,
    бывший тренер (после сброса спортсменом и после снятия роли админом),
    несуществующий sub → одинаковый 403 `forbidden`, хранилище спортсмена не
    изменилось;
  - выключенный переключатель → 403 `edit_not_allowed` на записи, `GET`
    по-прежнему 200;
  - без `base_version` → 400, устаревшая → 409, версия не создана;
  - план тренера не становится активным при наличии активного и становится,
    если активного нет;
  - архивный план → 404;
  - сознательно обновляются тесты #44 `test_athlete_data_is_read_only_for_the_coach`
    и `test_coach_routes_can_only_read_except_chat`: вместо «всё, кроме чата, —
    только GET» — явный список разрешённых тренеру POST; журнал, архив,
    активный план и DELETE по-прежнему 405.
- `tests/test_storage.py`: автор в версии и манифесте; история — порядок,
  лимит, нет почты, роль у версий без автора; `created_by_role` у плана
  тренера.
- `tests/test_coach_chat.py`: после правки ровно одно сообщение `plan_change`
  с `plan_id` и версией; непрочитанное у спортсмена, не у тренера; сбой записи
  чата не откатывает план и даёт `notified: false`.
- `tests/test_ai_coach.py`: применённое предложение пишет `author.role = ai`;
  правка тренера делает открытое предложение устаревшим.
- `tests/test_frontend_sanity.py`: экран тренера по-прежнему не пишет в свои
  данные и `localStorage`; новые обработчики существуют; конструктор
  спортсмена и тренера рисуется одной функцией; cache-buster поднят.

## Верификация

1. `python -m pytest` — весь набор зелёный.
2. Фронтенд — в браузерной панели на локально поднятой странице с подменённым
   `fetch` (Node в окружении нет): тренер создаёт план, правит недели, меняет
   гонку, импортирует CSV; устаревшая версия; выключенная правка; потеря
   доступа посреди правки. Спортсмен: переключатель, сообщение в чате,
   история.
3. Dev-стенд (`running-tracker-new-4ih.pages.dev`, бэкенд `runs-api-dev`), два
   одобренных аккаунта: A — тренер, B выбрал A.
   - A создаёт B план и правит неделю → у B новый план (не активный, если у B
     уже есть активный), сообщение в чате, запись в истории с именем A;
   - B открыл конструктор, A сохранил правку, B сохраняет → сообщение о
     конфликте и свежий план;
   - B выключает переключатель → у A пропадают кнопки, прямой `POST` даёт
     403 `edit_not_allowed`; просмотр работает;
   - B сбрасывает тренера → запись A даёт 403 `forbidden`;
   - собственные план, журнал и кэш A после работы с B не изменились.
4. PR `Dev → main` с `Closes #60`.

## Вне рамок

Правка с телефона для тренера, шаблоны и копирование плана между
спортсменами, комментарии к отдельным тренировкам, откат к версии одной
кнопкой (вернуться можно обычной правкой — история покажет, что было),
управление активным планом и архивом со стороны тренера, полная атомарность
записи (#35: сверка версии и запись, как и сейчас, идут двумя операциями;
реестр планов `index.json` при одновременной записи тренером и спортсменом
так же подвержен гонке в миллисекунды).
