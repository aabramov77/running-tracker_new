## Контекст

Issue: «Сейчас план для спортсмена можно либо создать вручную, либо
загрузить извне. Нужно сделать возможность создания нового плана с помощью
ИИ в режиме диалогов. План может быть как краткосрочный без определённой
цели по результату, например, поддержка текущей формы или улучшить
аэробную базу и т.д., так и подготовка к определённому старту с
определённой целью (просто финишировать, пробежать с определённым
временем)».

Что сейчас:

- ИИ-тренер (разборы, `kind` `run`/`general`) видит профиль, рекорды,
  нагрузку, историю и память, но план целиком не составляет — инструкция
  это запрещает (`llm_prompt.py`, раздел «Просьба составить план»).
- Правки плана от ИИ — только предложения по 4 ближайшим неделям
  активного плана (`clean_proposal` → `apply_ai_proposal`).
- Вызов модели: бюджет вывода 8000 токенов вместе с рассуждением,
  таймаут 60 с на вызов; Cloud Run — 300 с на запрос по умолчанию.

## Решение

Подробно — в `design.md` change. Коротко:

1. **Разбор «Новый план»** — вид `kind: "plan"` у разборов ИИ-тренера.
   Тот же ход, лимит, память и контекст; своя инструкция и формат ответа
   (`brief`, `outline` вместо `proposal`); окна правок активного плана нет.
2. **Бриф** — тип (`race`/`general`), название, даты, дистанция и цель
   (пусто — финишировать), тренировок в неделю, дни, день длительной,
   ограничения. Календарь недель считает сервер (первая неделя от даты
   начала до воскресенья, дальше пн–вс, до недели старта; не больше 30
   недель). Модель получает оценку цели: недели против минимума по
   дистанции и прогноз по Ригелю.
3. **Каркас** — по каждой неделе тип, акцент, км, ключевые тренировки, плюс
   ориентиры темпа; предупреждения о росте объёма и сроке. Отдельный шаг:
   после подтверждения брифа кнопкой.
4. **Недели** — кнопка «Расписать по неделям»: куски по 4 недели
   параллельными вызовами, вся генерация — одна попытка лимита. Даты, тип,
   акцент и день старта ставит сервер, модель пишет только тренировки
   дней. Сбой — ничего не записано, попытка возвращается.
5. **Черновик → план** только по действию спортсмена: «Создать план…» с
   выбором «Сделать активным» / «Активировать позже» или предпросмотр в
   конструкторе с правками. Версия 1 — черновик ИИ (автор `ai`), правки —
   версия 2 от спортсмена. Один план на черновик (`409 already_created`).

## Решения, согласованные с пользователем (2026-11-15)

1. Через ИИ-тренера — особый вид разбора, а не отдельный мастер.
2. Каркас — отдельным шагом с подтверждением.
3. Вся генерация недель — одна попытка дневного лимита.
4. Хватает существующих типов недель и полей карточки плана.
5. Активировать новый план — только после вопроса: спортсмен может
   захотеть поправить план или сделать по-другому. Отсюда выбор
   активации и предпросмотр черновика в конструкторе.

## Изменения по файлам

- `config.py` — константы плана от ИИ.
- `storage.py` — `kind` разбора, `clean_brief`, `brief_calendar`,
  `goal_assessment`, `clean_outline`, `outline_warnings`, ветка
  `kind == "plan"` в `build_ai_turn`, генерация недель кусками,
  `create_plan_from_draft`, `mark_draft_states`.
- `llm_prompt.py` — общая часть инструкции, `PLAN_BUILDER_SYSTEM_PROMPT`,
  `PLAN_WEEKS_PROMPT`, блоки брифа, оценки цели, каркаса и дней куска.
- `api.py` — `kind` в создании разбора, ход разбора «Новый план»,
  `POST …/messages/{msg}/weeks`, `POST …/messages/{msg}/create-plan`.
- `index.html`, `app.js`, `style.css` — кнопка «🤖 Составить с ИИ»,
  подсказка, пометка разбора, карточки брифа, каркаса и черновика,
  предпросмотр черновика в конструкторе, «от ИИ» в переключателе планов.
- Тесты — новый `tests/test_ai_plan_builder.py`, `test_ai_coach.py`,
  `test_routes.py`, `test_frontend_sanity.py`.
- `README.md` — раздел «ИИ-тренер».

## Верификация

- `pytest` целиком.
- Бриф, календарь, оценка цели, каркас и предупреждения — юнит-тесты по
  сценариям спеки.
- Ход разбора «Новый план» с моком модели: бриф и каркас в реплике,
  отклонённое — пометкой, `proposal` отброшен, обычный разбор не изменился.
- Генерация: 16 недель за 4 вызова; повтор неполного куска; `llm_bad_draft`
  без записи и без списания попытки; день старта и дни вне окна.
- Создание: без правок / с правкой (две версии), активация по выбору,
  повтор и гонка → один план, «план без недель» дописывается.
- Браузер (статический сервер + подменённый `fetch`): вход из «Плана»,
  карточки и кнопки по правилам, выбор активации, предпросмотр в
  конструкторе и «Отмена» без запросов, импорт файла не сломан, телефон
  без горизонтального скролла.
- Dev-стенд: реальная генерация плана на 16 недель (время, токены),
  `timeoutSeconds` сервиса Cloud Run.

## Вне этого тикета

- Правки черновика ячейками в формате предложений.
- Генерация плана тренером-человеком для своего спортсмена.
- Новый тип недели «База», поле цели в карточке плана.
- Просмотр и правка неактивного плана без активации.
- Отдельный лимит на генерации.
- Android-клиент.

## История решений

- 2026-11-15 — предложения по реализации, ответы пользователя на пять
  вопросов (выше), OpenSpec-изменение `ai-plan-builder`.
- 2026-11-15, при реализации:
  - чистая логика брифа, календаря, каркаса и недель — в отдельном
    `plan_builder.py` (как `compliance.py`, `load.py`); `storage.py` —
    только хранилище и запуск генерации;
  - план длиннее полугода подписывается датами с годом («16.11.2026»):
    подпись «ДД.ММ» читается с годом, ближайшим к началу плана, и дальше
    ~26 недель от начала год угадывался бы неверно;
  - цель «1:45» к полумарафону читается как 1 ч 45 мин: темп вне коридора
    забегов значит, что «м:сс» перепутано с «ч:мм»;
  - кусок, в ответе на который нет каких-то недель, переспрашивается
    только о них; при сбое куска ещё не начатые куски отменяются.

Сделано 2026-11-15 по `tasks.md` change. `pytest`: 1661 passed
(`tests/test_ai_plan_builder.py` — 90 тестов, плюс тесты вида разбора в
`test_ai_coach.py` и входов в `test_frontend_sanity.py`).

- Коммиты: `feat: #69 разбор «Новый план»: бриф, календарь, оценка цели,
  каркас`, `feat: #69 генерация недель по каркасу и создание плана из
  черновика`, `feat: #69 интерфейс: …`.
- Сквозная проверка фронтенда — jsdom с настоящими `index.html` и
  `app.js`, запросы в настоящий `api.handle_request` поверх `FakeBucket`
  с подменённой моделью (38 проверок): вход из «Плана» → бриф → «Всё
  верно» → каркас (предупреждение о скачке, после разгрузки — без него) →
  «Расписать по неделям» (одна попытка лимита) → «Создать план…» с выбором
  активации («Активировать позже» оставляет прежний план, «Сделать
  активным» загружает новый) → второй черновик в конструкторе: «Отмена»
  без единого запроса, правка ячейки → версия 2 от спортсмена;
  `already_created` переводит карточку в «создан»; импорт файла работает
  по-прежнему.
- Раскладка на телефоне — headless Edge, ширина 375 px: семь карточек
  (бриф, каркас, черновик, выбор активации) не выходят за экран,
  горизонтального скролла нет.
- Не проверено: реальная генерация на dev-стенде (время ответа модели,
  токены на 16 недель) и фактический `timeoutSeconds` сервиса Cloud Run —
  после пуша `Dev`.

## Замечено попутно

- Ручной план длиннее ~26 недель с подписями «ДД.ММ» читается с неверным
  годом у последних недель (`label_to_date` берёт год, ближайший к началу
  плана). Планы от ИИ подписываются с годом; для ручных — отдельный тикет,
  если такие планы бывают.
