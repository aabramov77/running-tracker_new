# #36 — Рефакторинг main.py

- Issue: https://github.com/aabramov77/running-tracker_new/issues/36
- Ветка: `Dev`
- Коммиты: `refactor: #36 …`

## Контекст

`main.py` — 2094 строки и 94 функции верхнего уровня. Сами секции когезивные
и подписаны, навигация терпимая. Болит другое:

**`runs_api` — 443 строки, 19 эндпоинтов в одной `if`-цепочке.** Корректность
зависит от порядка строк: `/advise/preview` обязан стоять выше `/advise`,
`/profile/history` — выше `/profile`. Ничто это не проверяет: новый маршрут,
поставленный не туда, молча перехватится соседом. `"Method not allowed"`
продублирован 16 раз, и при этом неизвестный метод на известном пути в одних
ветках даёт 405, а в других проваливается в 404.

**Блок советов LLM — 460 строк**, где перемешаны чтение из GCS, эвристики и
текстовое форматирование. Это самая часто изменяемая часть кода: каждая фича
вокруг ИИ идёт сюда.

Распределение по секциям на момент планирования:

| Строк | Секция |
|---:|---|
| 460 | Контекст и хранение советов LLM |
| 443 | HTTP-обработчик `runs_api` |
| 247 | Разбор FIT |
| 234 | Профиль спортсмена |
| 157 | Реестр планов |
| 100 | Реестр пользователей |
| ~450 | пути, runs, races, LLM-клиенты, миграция, auth |

## Рамки

Поведение не меняется. Контракт API остаётся прежним: те же пути, методы,
коды ответов и тела. Единственное намеренное изменение поведения — 405 вместо
404 при неизвестном методе на известном пути (фаза 2), это исправление
непоследовательности, а не новая семантика.

Страховка — существующие 133 теста. Каждая фаза отдельным коммитом, любую
можно смержить и остановиться.

## Две мины, специфичные для этого репозитория

**1. Фильтр путей в CD.** `.github/workflows/deploy-cloudrun.yml` следит
только за `main.py`, `requirements.txt` и самим воркфлоу. Как только код
уедет в новые модули, правки в них перестанут запускать деплой — и это худший
вид поломки: тесты зелёные, PR смержен, прод работает по старому коду.
Фильтр меняем на `'**.py'` **в том же коммите**, что и первый вынос кода.

`--source=.` заливает корень репозитория целиком, поэтому новые модули
деплоятся сами — упаковка не нужна.

**2. Тесты держатся за `main.py` как за модуль.** `tests/conftest.py` грузит
его через `spec_from_file_location` с заглушками google-модулей, и все 133
теста обращаются через `main_module.X`. При разносе нужно:

- добавить корень репозитория в `sys.path`, чтобы модули видели друг друга;
- ставить заглушки до импорта любого модуля (сейчас это уже делается на
  уровне conftest — порядок сохранится);
- решить, что делать с обращениями в тестах.

По второму пункту: **переписываем импорты в тестах**, а не оставляем в
`main.py` реэкспорт `from llm_prompt import *`. Фасад ради тестов — это
фасад, который потом никто не уберёт, и он маскирует настоящие зависимости.
Правки механические и затрагивают три файла тестов.

## Фазы

### Фаза 0 — мёртвый код

`INITIAL_PLAN` (13 недель исторического плана прямо в исходнике) и константы
`RACE_DATE`, `RACE_TARGET_TIME`, `RACE_TARGET_PACE`, `RACE_DISTANCE_KM`
встречаются в репозитории ровно по одному разу — в собственном определении.
Ни код, ни тесты, ни фронтенд их не используют: новые пользователи получают
пустой план, данные старых читаются из GCS.

Удаляем ~20 строк. В истории git они остаются.

Отдельный коммит, ничего не переносим — так изменение видно в диффе без шума
от переездов.

### Фаза 1 — общий словарь и слой промпта

Первый настоящий вынос делаем на самом безопасном материале: чистые функции
форматирования промпта не ходят в GCS и уже покрыты тестами.

Сразу всплывает первое проектное решение: `PLAN_DAYS` нужен и валидации
профиля (`clean_athlete_profile`), и форматированию промпта. Оставить его в
`main.py` нельзя — получится цикл (`main` импортирует `llm_prompt`,
`llm_prompt` импортирует `main`). Поэтому заводим третий, крошечный модуль
под общий словарь домена.

```
domain.py      PLAN_DAYS, PLAN_PHASE_LABELS, FEEL_LABELS, TYPE_LABELS,
               DIST_LABEL_KM, SEX_LABELS, HR_ZONE_BOUNDS
llm_prompt.py  plural_ru, format_profile_block, _week_days_str,
               format_context_for_llm, SYSTEM_PROMPT
main.py        остальное; импортирует оба модуля
```

`parse_time_to_sec` и `personal_bests` тоже чистые — переезжают в `domain.py`
как доменные вычисления, а не в слой промпта.

В этом же коммите: фильтр CD → `'**.py'`, `sys.path` в `conftest.py`,
импорты в `tests/test_main.py`.

### Фаза 2 — таблица маршрутов

```python
ROUTES = [
    ("GET",  r"^/profile$",              h_profile_get),
    ("POST", r"^/profile$",              h_profile_post),
    ("GET",  r"^/profile/history$",      h_profile_history),
    ("GET",  r"^/plans/([\w-]+)/weeks$", h_plan_weeks),
    ...
]
```

Диспетчер сначала собирает все маршруты с совпавшим путём, потом выбирает по
методу. Порядок объявления перестаёт влиять на корректность. Если путь
совпал, а метод нет — единый 405 с честным заголовком `Allow`.

Хендлеры получают один объект контекста: `request`, `bucket`, `sub`, `user`,
`is_admin` и группы из регулярного выражения. Проверка прав админа
переезжает в свойство маршрута, а не остаётся вложенным `if`.

`runs_api` ужимается до ~40 строк диспетчера плюс плоский список хендлеров.

Появляется тест, которого сейчас нет вовсе: проход по таблице с проверкой,
что пары «метод + путь» уникальны и ни один маршрут не забыл про авторизацию.

### Фаза 3 — разнос storage-слоя (по потребности)

`gcs_paths` / `storage_runs` / `storage_profile` / `storage_plans` /
`registry` / `fit`. Делаем только если после фаз 1–2 файл всё ещё мешает:
секции когезивны и подписаны, поэтому отдача здесь заметно ниже, а объём
переездов — наибольший.

## Верификация

По каждой фазе:

1. `pytest` зелёный — 133 теста, включая тесты промпта и хранилища.
2. Диффом убеждаемся, что перенесённый код не изменился по существу
   (переезд ≠ правка; если что-то надо поправить — отдельным коммитом).
3. Dev-стенд после деплоя: сохранить пробежку, открыть план, сохранить
   профиль, запросить предпросмотр контекста — то есть по одному эндпоинту
   из каждой затронутой группы.

Отдельно для фазы 1 — проверить, что деплой вообще запустился: workflow
должен отработать на коммит, который трогает только новые `.py`-файлы. Это
и есть проверка мины №1.

Отдельно для фазы 2 — `curl` на известный путь с неподдерживаемым методом:
ожидаем 405 и заголовок `Allow`, а не 404.

## Что специально не делаем

Гонка версий при одновременной записи (`write_athlete_version` и три её
ровесника вычисляют `N+1` без precondition) — это изменение поведения, а не
перекладывание кода. Ему нужен свой тикет и поддержка `if_generation_match`
в тестовом `FakeBucket`.
