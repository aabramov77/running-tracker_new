# #28 — Загрузка плана тренировок из файла

- **Issue:** [#28 Сделать функционал загрузки планов тренировок](https://github.com/aabramov77/running-tracker_new/issues/28)
- **Статус:** план (реализация не начата)

## Контекст

План сейчас можно составить только вручную через конструктор (`+ Неделя`,
правка ячеек). Для 13–16 недель это долго, а готовые планы обычно уже есть
в таблице (у пользователя лежит `training_plan_HM140_garmin_v3.xlsx`).

Нужно: загрузка плана из файла на вкладке «План», описанный формат и
возможность **поправить / принять / отклонить** загруженное перед сохранением.

## Согласованные решения

| Вопрос | Решение |
|---|---|
| Форматы | **CSV + JSON**. CSV — для подготовки в Excel/Sheets, JSON — точная структура + данные гонки |
| Выгрузка | **Шаблон-пример + экспорт текущего плана** (round-trip: выгрузить → править в Excel → загрузить) |

## Ключевое: работа целиком на фронте

Всё нужное уже есть и переиспользуется:

- `parseCSV()` — надёжный парсер (кавычки, многострочные ячейки) из Garmin-импорта
- `PLAN_DAYS` / `PLAN_TYPES` — канонические списки полей и типов недель
- Конструктор плана — режим правки уже умеет редактировать все ячейки
- `savePlanEdits()` → `POST /plan` — бэкенд уже пишет **новую версию** (история сохраняется)

**Бэкенд не меняется, редеплой Cloud Run не нужен.** Это чисто фронтовая задача.

## Формат файла

### CSV (основной для ручной подготовки)

```csv
Нед,Начало,Конец,Акцент,Тип,Пн,Вт,Ср,Чт,Пт,Сб,Вс
1,10.05,16.05,Развитие,dev,6–8 км легко,,"3×7 мин по 4:35–4:40",,8–10 км средний,8 км по 5:05,12 км легко
2,17.05,23.05,Развитие,dev,7–8 км легко,,"6×1 км по 4:30",,10 км средний,"4×2 км по 4:48",14–16 км легко
```

Правила разбора:

| Колонка | Синонимы (регистр не важен) | Обязательна |
|---|---|---|
| Номер недели | `Нед`, `Неделя`, `W`, `Week` | нет — нумеруется по порядку строк |
| Начало | `Начало`, `Старт`, `Start` | нет |
| Конец | `Конец`, `End` | нет |
| Акцент | `Акцент`, `Фокус`, `Accent` | нет |
| Тип | `Тип`, `Type` | нет — по умолчанию `dev` |
| Дни | `Пн`/`Mon`/`Понедельник` … `Вс`/`Sun`/`Воскресенье` | нет — отсутствующие дни пустые |

- Первая непустая строка — заголовок; неизвестные колонки игнорируются
  (перечисляются в предупреждениях).
- `Тип` принимает и код (`dev/peak/taper/load/race`), и подпись
  (`Развитие/Пик/Тейпер/Разгрузка/Старт`); неизвестное значение → `dev` + предупреждение.
- Пустые строки пропускаются. Нужна минимум одна строка данных.

### JSON (точная структура + данные гонки)

```json
{
  "format": "running-tracker-plan",
  "version": 1,
  "race": {
    "race_name": "Московский полумарафон",
    "race_date": "2026-08-09",
    "target_time": "1:40",
    "plan_start": "2026-05-10"
  },
  "weeks": [
    { "w": 1, "start": "10.05", "end": "16.05", "accent": "Развитие", "type": "dev",
      "mon": "6–8 км легко", "tue": "", "wed": "3×7 мин", "thu": "",
      "fri": "8–10 км средний", "sat": "8 км по 5:05", "sun": "12 км легко" }
  ]
}
```

- `race` — опционально; используется **только** при создании нового плана из файла.
- Голый массив недель (`[ {...}, ... ]`) тоже принимается.
- `format` / `version` необязательны; при неизвестной версии — предупреждение, не отказ.

## Поток загрузки: принять / поправить / отклонить

1. На вкладке «План» кнопка **«⤒ Загрузить план»** → выбор файла (`.csv`, `.json`).
2. Парсинг и валидация:
   - **Фатальные ошибки** (не распознан формат, нет строк данных) → показать список,
     текущий план **не трогать**.
   - **Предупреждения** (неизвестные колонки, некорректный тип) → показать, продолжить.
3. **Предпросмотр в конструкторе:** текущий план сохраняется в `_planBackup`,
   импортированные недели кладутся в `PLAN`, включается режим правки — пользователь
   видит план в обычной таблице и **может изменить любую ячейку**.
   Показывается import-бар:
   > Импортировано 13 недель из `plan.csv` · ⚠ предупреждения…
   > [Сохранить в текущий план] [Создать новый план] [Отменить импорт]
4. **Отменить импорт** → `PLAN = _planBackup`, выход из режима правки. Ничего не сохранено.
5. **Сохранить в текущий план** → существующий `savePlanEdits()` → `POST /plan`
   → новая версия плана (прежняя остаётся в истории).
6. **Создать новый план** → открывается форма создания (префилл из `race`, если JSON),
   после `POST /plans` недели уходят в `POST /plans/{id}/weeks`.

## Выгрузка

- **«⤓ CSV»** и **«⤓ JSON»** — экспорт текущего плана (JSON включает данные гонки).
- **«Шаблон»** — скачивает пример CSV с заполненными неделями: он же документация
  формата «на practice».
- Реализация: `Blob` + `URL.createObjectURL` + клик по `<a download>`.
  Имя файла: `plan-{race_name|training}-{YYYY-MM-DD}.{csv|json}`.

## Тестирование

Парсер живёт в JS, а сьют у нас на pytest, поэтому проверка двухслойная:

1. **pytest** (`test_plan_samples.py`) — гарантирует, что примеры в `docs/samples/`
   соответствуют задокументированному контракту: у JSON правильные поля недель и
   допустимые `type`; у CSV — ожидаемый заголовок и совпадение числа колонок в строках.
   Это защищает документацию и шаблоны от расхождения с кодом.
2. **Preview (`javascript_tool`)** — прогон реального парсера на этих же примерах:
   корректный разбор, синонимы колонок, неизвестный тип → `dev` + предупреждение,
   фатальная ошибка на мусорном файле, отмена импорта восстанавливает план,
   экспорт → повторный импорт даёт те же недели (round-trip).

## Верификация

1. `pytest` зелёный.
2. Preview: оба примера парсятся; CSV с русскими и английскими заголовками; файл
   без строк данных → ошибка и план не изменён; «Отменить импорт» возвращает прежний план.
3. Dev-стенд:
   - Загрузить CSV → предпросмотр в конструкторе → поправить ячейку → «Сохранить
     в текущий план» → перезагрузка страницы → правки на месте.
   - Загрузить JSON с `race` → «Создать новый план» → появился новый план с гонкой
     из файла и загруженными неделями; прежний план не изменился.
   - «⤓ CSV» → открыть в Excel → поправить → загрузить обратно (round-trip).
4. Прод: смоук — импорт небольшого файла и отмена.
