# #48 — UI в стиле мобильного приложения

- Issue: https://github.com/aabramov77/running-tracker_new/issues/48

- Коммиты: `feat: #48 фаза N — …`, в теле PR — `Closes #48`

## Контекст

На телефоне трекер сейчас выглядит как ужатый сайт: 9 вкладок в горизонтально
скроллящемся меню ([style.css:245](../../style.css)), таблица плана из 11 колонок с
`min-width: 560px` ([style.css:264](../../style.css)), четыре плитки метрик над каждым
экраном. Нужен интерфейс, который ощущается приложением: нижняя панель,
экран «Сегодня», план по дням, действия в выезжающих листах.

Согласовано:

| Вопрос | Решение |
|---|---|
| Нижняя панель | Сегодня · План · «+» · Прогресс · Ещё |
| План на телефоне | Одна неделя списком дней, стрелки листают недели |
| Редактирование | На телефоне — правка одного дня; конструктор, импорт и экспорт остаются на десктопе |
| Обёртка (PWA / TWA / WebView) | Отложена, в этот план не входит |

Принципы:

- **Один код, две раскладки.** Тот же `index.html`, мобильная раскладка
  включается на `max-width: 600px` (брейкпоинт уже есть). Десктоп не меняется.
- **Бэкенд не трогаем.** Все данные уже отдаются: недели плана, compliance с
  датами и статусами дней, пробежки.
- **Правка дня — новая версия плана** через существующий `postPlanWeeks`
  ([app.js:1181](../../app.js)), история сохраняется как при любой правке.

## Фаза 1 — каркас приложения

`index.html`
- `viewport`: добавить `viewport-fit=cover`; добавить `<meta name="theme-color">`.
- Кнопкам `.nav-btn` добавить `data-tab="…"` (вызовы `showTab('x',this)` не
  менять — на них завязаны тесты).
- Новый `<nav id="tabbar" class="tabbar">`: Сегодня, План, «+», Прогресс, Ещё.
- Новая вкладка `#tab-more`: строки ИИ-тренер, Старты, Профиль, Тренер (со
  счётчиком непрочитанных), Пользователи, Выйти.
- Переключатель `#progress-switch` «Журнал | Аналитика».
- Лист `#add-sheet` на классах `.run-detail-overlay` / `.run-detail-card`:
  Загрузить .fit, Загрузить .csv, Ввести вручную, Калькулятор темпа,
  Результат забега.

`app.js`
- `showTab(name, btn)` ([app.js:2264](../../app.js)) перестаёт зависеть от `btn`:
  активная кнопка ищется по `data-tab`, пункт нижней панели — по карте
  `TAB_GROUP` (`log`,`stats` → `progress`; `aicoach`,`races`,`profile`,
  `coach`,`users` → `more`). Ставит `document.body.dataset.tab = name`.
- `isMobile()` на `matchMedia('(max-width: 600px)')`; в `initApp`
  ([app.js:2834](../../app.js)) на телефоне стартовая вкладка — `today`.
- `openAddSheet()` / `closeAddSheet()`; пункты листа переходят на `add` и
  кликают по существующим `#garmin-fit-file` / `#garmin-file`.
- `applyRole` ([app.js:53](../../app.js)) и `refreshCoachBadge` ([app.js:2789](../../app.js))
  переводятся с одного `id` на выборку по атрибуту/классу, чтобы управлять и
  кнопкой в `.nav`, и строкой в «Ещё».

`style.css` (внутри `@media (max-width: 600px)`)
- `.nav` скрыт, `.tabbar` закреплён снизу с `env(safe-area-inset-bottom)`;
  `.app` получает нижний отступ под панель.
- `.metrics` видны только при `body[data-tab="today"]`; шапка компактная.
- `overscroll-behavior-y: contain`, `-webkit-tap-highlight-color: transparent`,
  `100dvh` вместо `100vh`, кнопки `.desktop-only` скрыты.
- В `#tab-add` калькулятор уезжает под форму (`order`).

## Фаза 2 — экран «Сегодня»

- Новая вкладка `#tab-today` и `renderToday()` в `app.js`; вызывается из
  `renderPlan()` вместе с таблицей и списком недели — так экран обновляется и
  после загрузки плана, и после `loadCompliance()`, и при изменении пробежек.
- Плитки метрик на телефоне видны только здесь и стоят в конце экрана.
- Карточка тренировки на сегодня: день ищется по `date` в
  `compliantWeeks()[getCurrentWeek()].days`; без дат — по дню недели от
  `weekStart(cw)`. Кнопки «Записать» → `openAddSheet()`, «Спросить ИИ» →
  `showTab('aicoach')`.
- Полоса недели: 7 кружков по статусам `done` / `missed` / `extra` + «сегодня»,
  рядом «факт / план км».
- Три последние пробежки через готовый `runItemHtml` ([app.js:1259](../../app.js)),
  ссылка «Весь журнал».
- Пустые состояния: нет плана, у плана нет дат (текст из
  `renderComplianceNote`).

## Фаза 3 — план неделей

- В `#tab-plan` добавить `<div id="plan-week">`; на телефоне таблица скрыта,
  на десктопе скрыт список.
- Из `planViewRowsHtml` ([app.js:781](../../app.js)) вынести наверх общие куски:
  `badgeMap` / `labelMap`, отметку факта (`factCell`) и подпись планового объёма
  с «≥» (из `kmCell`). Ими пользуются и таблица, и список.
- `planWeekHtml(plan, weeks, cw, idx)` — чистая функция по образцу
  `planViewRowsHtml`: шапка «Неделя N · даты», бейдж типа, «план / факт км»,
  семь строк дней.
- Состояние `planWeekIdx` (`null` = текущая неделя), `planWeekStep(±1)`;
  сбрасывается в `switchPlan`. `renderPlan()` в ветке просмотра рисует и
  таблицу, и список.
- Кнопки «Загрузить», «CSV», «JSON», «Шаблон», «Редактировать» получают
  `.desktop-only`. Выбор плана, «+ Новый план» и «Гонка» остаются.

## Фаза 4 — правка одного дня

- Лист `#day-sheet`: заголовок «Ср, 7 окт · неделя 5», `textarea` с текстом
  плана, «Сохранить» / «Отмена». Открывается тапом по строке дня.
- `saveDayEdit()`:
  1. отказ, если идёт конструктор или предпросмотр импорта (как в
     `aiApplyProposal`);
  2. перечитать `GET plan` и сравнить ячейку со значением на момент открытия
     листа; расхождение → сообщение «План изменился», `loadPlan()`, без записи;
  3. копия недель с одной изменённой ячейкой →
     `postPlanWeeks(weeks, 'Правка дня: нед N, Ср')`;
  4. `await loadPlan()` — перерисовка и свежий compliance.
- Ограничение: `POST plan` на сервере версию не сверяет ([api.py:661](../../api.py)),
  шаг 2 только сужает окно гонки. Серверная проверка версии — отдельный тикет.

## Фаза 5 — доводка экранов

- Карточка пробежки и остальные листы: на телефоне на всю ширину,
  `max-height: 92dvh`, «ручка» сверху, отступ под safe-area.
- ИИ-тренер и чат с тренером: поле ввода прилипает к низу над панелью, список
  разборов укорочен до двух-трёх строк (сворачивать не стали — хватило высоты).
- Основные кнопки форм — на всю ширину.
- Экран тренера (план спортсмена) остаётся таблицей со скроллом — вне объёма.
- `README.md`: абзац про мобильную раскладку; поднять `?v=` у `app.js` и
  `style.css` в `index.html`.

## Тесты

В `tests/test_frontend_sanity.py`, тем же статическим способом:

- каждому `id="tab-…"` в `index.html` соответствует ключ в `TAB_GROUP`, и
  каждому `showTab('x'` — существующий `id="tab-x"`;
- `#tabbar`, `#tab-today`, `#tab-more`, `#plan-week`, `#add-sheet`,
  `#day-sheet` на месте, `viewport-fit=cover` есть;
- в `saveDayEdit` запись идёт через `postPlanWeeks`, после неё стоит
  `await loadPlan()`, есть проверка `planEditMode`;
- существующие проверки обработчиков (`test_inline_handlers_point_at_existing_functions`)
  и изоляции разделов ИИ-тренера и тренера проходят без правок.

## Верификация

1. `python -m pytest -q` после каждой фазы (хук post-commit запускает его сам).
2. Локальный просмотр: статический сервер + встроенный браузер в режиме

   пройдёт, поэтому локально проверяется раскладка и пустые состояния.

   недель; правка дня и появление новой версии плана; «Ещё» → ИИ-тренер;
   счётчик непрочитанных у тренера.
4. Десктоп (ширина > 600px): вкладки, таблица плана и конструктор работают
   как раньше.
