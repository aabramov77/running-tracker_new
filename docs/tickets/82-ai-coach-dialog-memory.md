## Контекст

После #80 пользователь проверил тренера на dev-стенде. Отдельные факты — не
то, чего он ждал. Нужно, чтобы тренер помнил контекст диалогов, как в чатах
Claude и ChatGPT.

Модель получала только последние 12 реплик разбора (`AI_HISTORY_WINDOW`):
- в длинном разговоре терялось начало;
- новый разбор не знал, о чём говорили в прошлых.

Решение пользователя:
- тренер помнит весь текущий разбор и краткое содержание прошлых;
- факты из #80 остаются.

## Решение

### Весь разбор — по объёму, а не по числу реплик

- `ai_history_start(messages, budget)` берёт самые свежие реплики, пока их
  текст помещается в `AI_HISTORY_CHARS = 40000` символов. Обычный разбор
  уходит модели целиком.
- В начале окна всегда вопрос — этого ждут провайдеры.
- Последний вопрос с ответом уходят всегда, даже если вдвоём они больше
  лимита.
- У длинного разбора отброшенное начало заменяет блок «=== Начало этого
  разбора ===» с его кратким содержанием (`format_thread_start`).
- Пробежки в фокусе по-прежнему берутся из 12 последних реплик
  (`AI_FOCUS_WINDOW`): подробный блок по давно упомянутой пробежке стоит
  токенов, а разговор ушёл дальше.

### Краткое содержание пишет модель в каждом ответе

- В обоих форматах ответа новый ключ `summary`: краткое содержание всего
  разбора на сейчас — о чём спрашивал спортсмен, что посоветовано, о чём
  договорились, что осталось открытым. 3–6 предложений, до 800 символов,
  от третьего лица.
- Сервер чистит его (`clean_thread_summary`): одна строка, не длиннее
  `AI_SUMMARY_MAX = 1000`. Хранит в реплике ответа как `thread_summary` —
  новых объектов в GCS не появляется.
- Модель не дала содержания — в реплику переносится прежнее
  (`latest_thread_summary`). Поэтому последняя реплика тренера всегда несёт
  свежее содержание разбора.
- В конверте истории (`ai_history`) `summary` есть только у последнего
  ответа: у каждого оно повторяло бы почти то же самое. Последнего хватает,
  чтобы модель не потеряла ключ формата.

Почему не отдельный вызов модели для сжатия:
- ни лишних вызовов, ни логики, решающей, когда сжимать;
- содержание всегда свежее.

Цена — около 300 токенов вывода на ответ.

### Прошлые разборы

- `past_ai_threads(bucket, sub, exclude_id)` — до `AI_PAST_THREADS = 5`
  последних разборов, кроме текущего, скрытые не берутся. Название, время
  последней реплики и краткое содержание из последней реплики тренера.
- Список и свежесть — из имён объектов одним `list_blobs`, общим с
  `list_ai_threads` (`_visible_ai_threads`). На разбор — карточка и одна
  реплика, параллельно: до 10 чтений на ход.
- Блок «=== Прошлые разборы (кратко, сначала свежие) ===» идёт за памятью
  фактов. У первого разбора блока нет.
- У разборов до этой фичи — «краткого содержания нет». Оно появится после
  первого нового ответа в таком разборе.

### Инструкция

Раздел «Память о разговорах»:
- как писать `summary`;
- прошлые разборы — память о прошлых разговорах. Если нужных деталей там
  нет, сказать об этом прямо, не додумывать;
- где искать начало длинного разбора.

Порядок блоков данных: данные спортсмена → память фактов → прошлые разборы →
начало этого разбора → окно плана → выбранные тренировки.

### Интерфейс

- В открытом разборе — свёрнутая строка «🧠 Тренер помнит об этом разборе».
  Внутри — краткое содержание из последнего ответа, только текстом
  (`textContent`). Лишних запросов нет: реплики уже загружены.
- Подсказка на пустом экране: тренер помнит весь разговор и прошлые разборы.
- `app.js?v=56`, `style.css?v=35`.

## Тесты

`tests/test_ai_dialog_memory.py` (новый, 18 тестов):
- краткое содержание:
  - чистка и предел;
  - выбор самого свежего;
  - только у последнего ответа в конверте;
  - сохранение в реплике и перенос прежнего;
  - без содержания — поля нет;
- весь разбор: обычный уходит целиком; у длинного — блок начала с кратким
  содержанием;
- прошлые разборы:
  - новый разбор видит прошлые, свежие первыми, без текущего;
  - у первого разбора блока нет;
  - скрытые не берутся;
  - не больше 5;
  - старые без содержания;
  - блок есть в `/advise/preview`;
- промпт: строки блоков, порядок, инструкция в обоих форматах.

`tests/test_ai_coach.py`: тесты окна из 12 реплик заменены тестами лимита по
объёму, в том числе «последняя пара уходит всегда». Тест фокуса — на
`AI_FOCUS_WINDOW`.

`tests/test_frontend_sanity.py`: строка краткого содержания размечена и
заполняется текстом.

## Отличия от плана

- Последний вопрос с ответом уходят модели всегда, даже сверх лимита. Иначе
  при одном очень длинном ответе история оказалась бы пустой.

## Вне рамок

- Краткое содержание в списке разборов — на каждый разбор понадобилось бы
  лишнее чтение.
- Поиск по всем прошлым разборам: модель видит только 5 последних.
- Отдельная правка краткого содержания спортсменом. Для того, что нужно
  помнить точно, есть факты #80.
