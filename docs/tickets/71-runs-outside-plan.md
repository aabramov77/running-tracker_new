## Контекст

Issue: «Сейчас проведённую тренировку можно привязать только к существующему
плану. Нужно дать возможность спортсмену сохранять и анализировать пробежки
даже, если у него ещё нет плана или тренировка попадает на дату между
планами».

Что сейчас:

- Новая пробежка без `plan_id` уходит в **активный** план при любой дате
  (`h_runs_post` → `save_run(default_plan_id=активный)`). Пробежка до старта
  плана, после окончания или между планами искажает его план/факт.
- Форма не умеет «без плана»: список `f-plan` — только неархивные планы,
  по умолчанию стоит на активном, скрыт без планов. Пустой `plan_id` сервер
  понимает как «по умолчанию», поэтому и отвязать пробежку правкой нельзя.
- Правка пробежки архивного плана перепривязывает её к активному: архивного
  плана в списке нет, а выбор остаётся на активном.
- Журнал и аналитика знают только области «текущий план» и «все». Метка
  «Нед N» считается по окнам активного плана для любой пробежки.

## Решение

Подробно — в `design.md` change. Коротко:

1. **API.** Ключ `plan_id: null`/`""` — «без плана», ключа нет — «по
   умолчанию». Признак переносится отсутствием ключа: `clean_run` кладёт
   `plan_id` только если он был в теле, `save_run` применяет умолчание только
   при отсутствии ключа.
2. **Привязка по дате** (`plan_for_date` в `storage.py`) для новой пробежки
   без ключа: датированные планы, включая архивные; диапазон — от начала
   первого до конца последнего окна недель (`week_windows`); приоритет у
   активного, затем у позже начавшегося. Ничего не подошло, а у активного
   плана диапазон неизвестен (недель нет или они без дат) → активный план.
   Иначе — без плана.
3. **Форма.** «Авто (по дате)» (по умолчанию), «Без плана», планы. При
   правке «Авто» нет, архивный план пробежки — в списке с пометкой
   «(архив)». После сохранения и после правки выбор возвращается к «Авто».
4. **Область «Без плана»** в журнале и аналитике; недельный график в ней
   скрыт. «Нед N» — только у пробежек активного плана, в журнале и на
   экране «Сегодня».

## Верификация

- `pytest` целиком.
- Юнит-тесты `plan_for_date`: между планами, после окончания активного,
  только неактивный, только архивный, два плана, нет планов, недатированный
  активный, активный без недель, датированный архивный важнее
  недатированного активного.
- Маршрут `POST /`: без ключа — по дате; `plan_id: null` — без плана;
  отвязка правкой — новая версия, прежняя в истории; при правке недели
  планов не читаются.
- Браузер (статический сервер + подменённый `fetch`):
  - тело запроса для «Авто», «Без плана», конкретного плана;
  - правка пробежки без плана и пробежки архивного плана;
  - сброс к «Авто» после правки и после сохранения;
  - кнопки области синхронны в журнале и аналитике; «Без плана» — только
    пробежки с `plan_id: null`, пустое сообщение;
  - недельный график скрыт в «Без плана» и виден с нормальным размером
    после возврата в «Все»;
  - «Нед N» нет у пробежки вне активного плана в журнале и на «Сегодня».

## Вне этого тикета

- Аналитика по календарным неделям без плана (захардкоженный старт
  `2026-05-10`, «из 13»).
- Массовая перепривязка сохранённых пробежек.
- Область «Без плана» в карточке спортсмена у тренера.
- Пробежка, сохранённая без связи, на сервер не отправляется и теряется при
  следующей загрузке журнала — существующая проблема, нужен отдельный тикет.
- Android-клиент.

## История решений

- 2026-11-13 — OpenSpec-предложение: привязка по дате, явное «без плана»,
  область «Без плана».
- 2026-11-14 — после сверки с кодом:
  - правка пробежки архивного плана сохраняет привязку (план в списке с
    пометкой «(архив)»);
  - после правки и сохранения список возвращается к «Авто», при правке
    «Авто» нет;
  - новые пробежки попадают в активный план; без плана — только если в эту
    дату нет ни активного, ни архивного плана; недатированный активный план
    получает пробежки, не попавшие в датированные планы;
  - недельный график в области «Без плана» скрыт.
