# #56 — Ручная корректировка пульсовых зон

- Issue: https://github.com/aabramov77/running-tracker_new/issues/56
- Ветка: `Dev`
- Коммиты: `feat: #56 …`

## Контекст

Пять пульсовых зон считались только автоматически: `compute_athlete_derived`
брал максимальный пульс (измеренный или оценку Танаки) и фиксированные
проценты 50/60/70/80/90–100 из `domain.HR_ZONE_BOUNDS`. В профиле зоны не
хранились и не редактировались.

Зоны — не только картинка в профиле. По ним `hr_zone_minutes` считает «время
в зонах» для разбора тренировки ИИ-тренером (#46). У кого реальные зоны — по
тесту, по часам, по ПАНО — не совпадают с процентами от HRmax, тот получал
неверный разбор и поправить ничего не мог.

## Решения

| Вопрос | Решение |
|---|---|
| Что хранить | Поле профиля `hr_zones_custom`: `null` (расчёт) или 5 целых — нижние границы Z1…Z5, уд/мин |
| Почему только нижние границы | Зоны и так смежные: у расчётных `to` равен `from` следующей, а `hr_zone_minutes` смотрит только на `from`. Верх Z5 — максимальный пульс; отдельное поле стало бы вторым HRmax |
| Можно ли поправить одну границу | Нет, зоны задаются все разом. В смешанном режиме смена HRmax сдвигает расчётные границы через ручные |
| Как править удобно | При включении ручного режима поля заполняются расчётными значениями — остаётся подвинуть нужные |
| Сверять ли с HRmax | Начало Z5 — строго ниже измеренного. С оценкой по возрасту не сверяем: зоны правят как раз те, у кого она врёт |
| Нужна ли миграция | Нет. Версия без поля читается как `null` — `read_athlete_profile` накладывает сохранённое на пустой профиль |
| Версионирование | Уже есть: поле живёт в профиле, каждое сохранение — новая версия `athlete/v{N}/profile.json`. Сброс к расчёту — тоже новая версия, ручные зоны остаются в истории |

## Изменения

### Бэкенд — `storage.py`

- `clean_hr_zone_starts(value, hr_max)` — проверка поля: список ровно из пяти
  чисел в пределах 30–230, строго по возрастанию, начало Z5 ниже измеренного
  HRmax. Любое нарушение — `400 validation_failed` с полем `hr_zones_custom`;
  значение не того типа даёт тот же отказ, а не 500 (#53).
- `compute_athlete_derived` отдаёт три поля:
  - `hr_zones` — действующие зоны (ручные, если заданы, иначе расчётные);
  - `hr_zones_auto` — всегда расчётные, с них начинается ручная правка;
  - `hr_zones_source` — `manual` / `auto`.
- У ручной Z5 `to` — действующий HRmax, если он выше её начала, иначе `null`.
- Сохранённое поле неверной формы игнорируется — чтение остаётся терпимым.
- `build_run_focus` помечает разбор флагом `zones_manual`. `hr_zone_minutes`
  не менялся: он получает те же `{name, from, to}`.

### Промпт — `llm_prompt.py`

- Блок профиля: строка `Пульсовые зоны (заданы спортсменом): Z1 100–125, …`
  печатается только для ручных зон. Расчётные по-прежнему идут в промпт
  одними именами, промпт остальных пользователей не изменился.
- Блок пробежки: основание времени в зонах — «границы заданы спортсменом»
  вместо «макс. пульс N».

### Фронтенд — `index.html`, `app.js`, `style.css`

- Секция «Пульсовые зоны» после «Физиологии». Зоны показываются и правятся в
  одном месте; из нижнего блока вычисленного они ушли.
  - Расчёт: зоны плашками и кнопка «Настроить вручную».
  - Вручную: пять строк «от … до …», верх подставляется на лету из следующего
    поля; кнопка «Вернуть авторасчёт».
- Разметка редактора статична, JS ставит только `.value` — данные сервера не
  попадают в `innerHTML` мимо `escapeHtml` (#53).
- `collectProfileForm` шлёт список границ или `null`.

## API

Контракт `/profile` расширен, старые клиенты не ломаются:

```
POST /profile  {"profile": {…, "hr_zones_custom": [100, 125, 140, 155, 168]}}   // или null
GET  /profile  → {"profile": {…, "hr_zones_custom": […] | null},
                  "derived": {…, "hr_zones": […], "hr_zones_auto": […],
                              "hr_zones_source": "manual" | "auto"}}
```

## Не входит

- Выбор метода расчёта (от ПАНО, по Карвонену с пульсом покоя). ПАНО и пульс
  покоя в профиле есть и в зонах не участвуют — это отдельная фича.
- Показ зон спортсмена тренеру, график истории зон.

## Верификация

1. `python -m pytest` зелёный.
2. Фронтенд в браузере со статическим сервером и подменённым `fetch`:
   расчёт → плашки; «Настроить вручную» → поля заполнены расчётными; правка и
   сохранение → в теле `hr_zones_custom: […]`; отказ 400 показан как
   «Пульсовые зоны — …»; «Вернуть авторасчёт» → `null`; ширина 375px.
3. Dev-стенд: два сохранения → поле есть в новой версии, предыдущая не
   тронута; «Показать контекст для ИИ» содержит строку зон; разбор тренировки
   с FIT считает время по ручным границам.
