# landing-page Specification

## Purpose
Что видит посетитель до входа и как он входит: стартовая страница с описанием возможностей, вход через Google, One Tap для вернувшихся, заставка при свежем токене, экраны статуса заявки и выбор стенда по адресу страницы.

## Requirements

### Requirement: Стартовая страница для гостя
Посетитель без действующего токена SHALL видеть стартовую страницу вместо приложения: описание возможностей (планы и календарь, план против факта, импорт из Garmin, недельная нагрузка, ИИ-тренер, свой тренер), разделы «Возможности», «Тренерам», «Как начать» и кнопки «Войти через Google». Страница MUST заранее предупреждать, что доступ выдаётся по заявке после одобрения администратором.

#### Scenario: Первый визит
- **WHEN** новый посетитель открывает сайт
- **THEN** видит стартовую страницу с кнопкой входа и пометкой «Доступ по заявке»

### Requirement: Вход через Google
Вход SHALL идти через Google Identity Services с клиентом приложения. Полученный токен MUST сохраняться в браузере и отправляться с каждым запросом к API; после входа показывается заставка, пока сервер подтверждает доступ.

#### Scenario: Нажатие «Войти через Google»
- **WHEN** посетитель входит через Google
- **THEN** вместо стартовой страницы — заставка «Загрузка…», затем приложение или экран статуса

### Requirement: One Tap только для вернувшихся
Окно One Tap SHALL предлагаться само только тому, кто уже входил на этом устройстве; новому посетителю MUST показываться стартовая страница без всплывающего окна. После «Выйти» One Tap сам не всплывает. В течение 5 минут после получения токена One Tap не предлагается, чтобы не входить по кругу.

#### Scenario: Истёк часовой токен
- **WHEN** вернувшийся пользователь открывает сайт с истёкшим токеном
- **THEN** стартовая страница предлагает One Tap, и вход возвращается без лишних кликов

#### Scenario: После выхода
- **WHEN** пользователь нажал «Выйти» и снова открыл сайт
- **THEN** One Tap сам не появляется

### Requirement: Заставка при свежем токене
При открытии сайта со свежим (не истекающим в ближайшую минуту) токеном интерфейс SHALL показывать заставку и сразу запрашивать статус доступа, не показывая стартовую страницу. Свежесть токена в браузере MUST решать только выбор экрана; доступ проверяет сервер.

#### Scenario: Повторное открытие вкладки
- **WHEN** пользователь со свежим токеном открывает сайт
- **THEN** стартовая страница не мелькает, сразу заставка и приложение

### Requirement: Экраны статуса заявки
Пользователю со статусом `pending` SHALL показываться экран «⏳ Заявка на рассмотрении», с иным неодобренным статусом — «⛔ Доступ отклонён»; на обоих MUST быть кнопка «Выйти».

#### Scenario: Заявка ждёт одобрения
- **WHEN** новый пользователь вошёл, а администратор ещё не одобрил его
- **THEN** он видит «Заявка на рассмотрении» и кнопку «Выйти»

### Requirement: Выход
«Выйти» SHALL удалять токен и отметку прежнего входа, сбрасывать состояние пользователя в интерфейсе и показывать стартовую страницу. Автовыбор аккаунта Google MUST отключаться.

#### Scenario: Выход на общем компьютере
- **WHEN** пользователь нажимает «Выйти»
- **THEN** показывается стартовая страница, данные пользователя на экране не остаются

### Requirement: Выбор стенда
Интерфейс SHALL обращаться к рабочему API, только когда открыт с адреса прода, и к API dev-стенда с любого другого адреса. Вне прода MUST показываться бейдж `DEV` в углу экрана.

#### Scenario: Dev-стенд
- **WHEN** интерфейс открыт с адреса dev-стенда
- **THEN** запросы идут в API dev-стенда, в углу бейдж `DEV`
