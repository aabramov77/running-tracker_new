# llm-config Specification

## Purpose
Настройка языковой модели, на которой работает ИИ-тренер: провайдер, модель, ключ и глубина рассуждения задаются администратором и общие для всех пользователей. Ключ никогда не возвращается клиенту.

## Requirements

### Requirement: Только администратор
Маршруты `GET /config/llm`, `POST /config/llm` и `POST /config/llm/test` SHALL быть доступны только администратору; остальным — `403 forbidden`. В интерфейсе настройки MUST быть в «Профиле» только у администратора; остальные видят пометку, что ИИ-тренер настроен администратором.

#### Scenario: Обычный пользователь открывает профиль
- **WHEN** пользователь без роли администратора открывает «Профиль»
- **THEN** вместо настроек модели — пометка «ИИ-тренер настроен администратором приложения»

### Requirement: Чтение конфига без ключа
`GET /config/llm` SHALL отдавать `{"configured": false}`, если модель не настроена, иначе — версию, провайдера, модель, маску ключа (первые 6 и последние 4 символа, короткий ключ — `***`), глубину рассуждения, допустимые уровни, уровень по умолчанию и время записи. Сам ключ MUST NOT отдаваться ни одним маршрутом.

#### Scenario: Маска ключа
- **WHEN** администратор открывает настройки с ключом длиной 40 символов
- **THEN** видит маску вида `sk-abc***wxyz`, но не ключ

### Requirement: Запись конфига
`POST /config/llm` с `{"provider", "model", "api_key", "effort"?}` SHALL записывать новую версию конфига и отвечать `201` с версией, провайдером, моделью и уровнем. Провайдер MUST быть `openai`, `deepseek` или `anthropic`, иначе `400 Invalid provider`; модель и ключ — строки (`400 Invalid model` / `Invalid api_key`), непустые (`400 Missing model` / `Missing api_key`); ключ обрезается по краям.

#### Scenario: Ключ с пробелом
- **WHEN** администратор вставляет ключ с пробелом в конце
- **THEN** сохраняется ключ без пробела

#### Scenario: Пустой ключ
- **WHEN** администратор сохраняет конфиг без ключа
- **THEN** ответ `400 Missing api_key`, версия не создаётся

### Requirement: Глубина рассуждения
Глубина рассуждения SHALL быть `low`, `medium` или `high`, по умолчанию `medium`; иное значение при записи MUST давать `400 Invalid effort` со списком допустимых. Сохранённый неизвестный уровень при вызове модели заменяется уровнем по умолчанию.

#### Scenario: Неизвестный уровень
- **WHEN** администратор сохраняет `effort: "max"`
- **THEN** ответ `400 Invalid effort` с `allowed: ["low", "medium", "high"]`

### Requirement: Версии конфига
Каждое сохранение конфига SHALL быть новой неизменяемой версией; прежние версии MUST оставаться, а ответы ИИ-тренера хранят номер версии конфига, на которой получены.

#### Scenario: Смена модели
- **WHEN** администратор меняет модель
- **THEN** появляется новая версия, следующие ответы ссылаются на неё

### Requirement: Проверка ключа
`POST /config/llm/test` SHALL отправлять модели короткий тестовый запрос и отвечать `200` с `ok: true`, задержкой, числом токенов и началом ответа либо `ok: false` с причиной, в том числе с кодом и текстом ответа провайдера. Без конфига ответ MUST быть `400 {"ok": false, "error": "LLM config not set"}`.

#### Scenario: Неверный ключ
- **WHEN** администратор проверяет конфиг с отозванным ключом
- **THEN** ответ `200` с `ok: false` и кодом ответа провайдера

### Requirement: Провайдеры в интерфейсе
Интерфейс SHALL предлагать провайдеров OpenAI и DeepSeek со списком моделей каждого. Конфиг с провайдером, которого нет в списке, MUST открываться с первым доступным провайдером.

#### Scenario: Сохранён провайдер вне списка
- **WHEN** текущий конфиг записан с провайдером `anthropic`
- **THEN** форма настроек открывается с провайдером из списка

### Requirement: Вызов модели
Запрос к OpenAI и DeepSeek SHALL идти в режиме JSON-ответа с глубиной рассуждения и бюджетом вывода 8000 токенов, покрывающим и рассуждение. Отказ модели или фильтр провайдера MUST распознаваться как отказ, обрыв по бюджету — как обрыв, пустой ответ — как ошибка; история разбора передаётся репликами между системной частью и новым вопросом.

#### Scenario: Ответ оборван по бюджету
- **WHEN** провайдер завершил ответ по исчерпанию бюджета
- **THEN** ход диалога завершается ошибкой `llm_truncated`

### Requirement: Настройки модели в режиме просмотра
У администратора настройки модели в «Профиле» SHALL быть блоком с режимом просмотра: провайдер, модель, глубина рассуждения и маска ключа текстом либо «не настроено». Форма с кнопками «Сохранить» и «Отмена» MUST раскрываться только по «Изменить»; «Отмена» очищает введённый ключ и не создаёт версию.

#### Scenario: Модель настроена
- **WHEN** администратор с сохранённым конфигом открывает «Профиль»
- **THEN** блок показывает провайдера, модель, глубину и маску ключа текстом, полей формы на экране нет

#### Scenario: Модель не настроена
- **WHEN** администратор открывает «Профиль», а конфиг ещё не записан
- **THEN** блок показывает «не настроено» и кнопку «Изменить»

### Requirement: Ключ при сохранении настроек модели
Форма настроек модели SHALL пояснять, что ключ нужно вводить при каждом сохранении. Сохранение без ключа MUST оставлять блок открытым с ошибкой под полем ключа и не создавать версию; после успешного сохранения поле ключа очищается, а блок возвращается в просмотр с новыми значениями.

#### Scenario: Сохранение без ключа
- **WHEN** администратор меняет модель, оставляет поле ключа пустым и нажимает «Сохранить»
- **THEN** под полем ключа ошибка «Введите API-ключ», блок открыт, версия конфига не создана

#### Scenario: Смена модели
- **WHEN** администратор меняет модель, вводит ключ и сохраняет
- **THEN** блок в просмотре показывает новую модель и маску ключа, поле ключа пустое

### Requirement: Проверка сохранённого ключа из просмотра
Кнопка «Проверить ключ» SHALL быть в режиме просмотра блока и проверять сохранённый конфиг. Пока конфиг не записан, кнопка MUST быть недоступна; в открытой форме кнопки нет, чтобы её не принимали за проверку введённого ключа.

#### Scenario: Проверка без конфига
- **WHEN** администратор открывает блок с ненастроенной моделью
- **THEN** кнопка «Проверить ключ» недоступна

#### Scenario: Форма открыта
- **WHEN** администратор нажал «Изменить»
- **THEN** в блоке нет кнопки «Проверить ключ», только «Сохранить» и «Отмена»
