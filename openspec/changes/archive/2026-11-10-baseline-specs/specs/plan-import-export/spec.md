# Spec Delta

## Purpose

Загрузка плана тренировок из файла CSV или JSON с проверкой и предпросмотром в конструкторе, выгрузка текущего плана в те же форматы и шаблон для подготовки плана в таблице.

## ADDED Requirements

### Requirement: Распознавание формата файла
Загрузка SHALL принимать файл CSV или JSON в UTF-8: JSON — если имя оканчивается на `.json` или текст начинается с `[` или `{`, иначе CSV. BOM в начале файла MUST игнорироваться. Разбор идёт в браузере, на сервер до сохранения ничего не уходит.

#### Scenario: CSV из Excel с BOM
- **WHEN** спортсмен загружает CSV, сохранённый Excel с BOM
- **THEN** заголовок распознаётся так же, как без BOM

### Requirement: Колонки CSV
Первая непустая строка CSV SHALL быть заголовком; колонки сопоставляются по синонимам без учёта регистра: номер (`Нед`, `Неделя`, `№`, `W`, `Week`), даты (`Начало`/`Старт`/`Start`, `Конец`/`Окончание`/`End`), акцент (`Акцент`/`Фокус`/`Accent`/`Focus`), тип (`Тип`/`Type`/`Фаза`/`Phase`) и дни (`Пн`…`Вс`, полные русские и английские названия). Без колонки дня файл MUST отклоняться.

#### Scenario: Нет ни одного дня недели
- **WHEN** в заголовке CSV только `Нед,Начало,Конец`
- **THEN** загрузка отклоняется с ошибкой о колонках дней, план не меняется

#### Scenario: Английский заголовок
- **WHEN** заголовок `Week,Start,Mon,Sun`
- **THEN** колонки распознаются как номер, начало, понедельник и воскресенье

### Requirement: Строки CSV
Неизвестные колонки SHALL игнорироваться и перечисляться в предупреждении. Пустые строки MUST пропускаться; нужна хотя бы одна строка данных. Ячейка в двойных кавычках может содержать запятые, переводы строк и удвоенные кавычки. Отсутствующие дни — пустые (отдых); недели нумеруются по порядку строк.

#### Scenario: Только заголовок
- **WHEN** в CSV есть заголовок и ни одной строки данных
- **THEN** ошибка «нет строк с данными»

#### Scenario: Ячейка с запятой
- **WHEN** ячейка дня записана как `"3×7 мин, пауза 3:00"`
- **THEN** тренировка дня — `3×7 мин, пауза 3:00`

### Requirement: Тип недели при загрузке
Тип недели SHALL приниматься кодом (`dev`, `peak`, `taper`, `load`, `race`) или подписью («Развитие», «Пик», «Тейпер», «Разгрузка», «Старт») без учёта регистра. Пустой тип — `dev`; неизвестный MUST становиться `dev` с предупреждением, где указана строка.

#### Scenario: Неизвестный тип
- **WHEN** в колонке типа значение «Базовая»
- **THEN** неделя получает тип `dev` и предупреждение «неизвестный тип «Базовая» → Развитие»

### Requirement: Формат JSON
JSON SHALL быть объектом с массивом `weeks` (необязательно `format: "running-tracker-plan"`, `version`, `race`) или массивом недель. Пустой список недель и иной формат MUST отклоняться ошибкой. `version` больше 1 даёт предупреждение. Недели перенумеровываются по порядку, поля дней приводятся к строкам.

#### Scenario: Голый массив недель
- **WHEN** спортсмен загружает `[{"w": 1, "mon": "8 км легко"}]`
- **THEN** в предпросмотре одна неделя с понедельником «8 км легко»

### Requirement: Ошибка загрузки не меняет план
Если разбор файла дал ошибки, интерфейс SHALL показать их списком, а текущий план MUST остаться без изменений.

#### Scenario: Некорректный JSON
- **WHEN** спортсмен загружает файл `.json` с синтаксической ошибкой
- **THEN** видит «Некорректный JSON» и прежний план

### Requirement: Предпросмотр перед сохранением
Разобранный план SHALL открываться в конструкторе без записи на сервер, с числом недель, предупреждениями разбора и предупреждениями о датах (пересечение строк, тренировка в дне вне дат строки). Спортсмен MUST иметь возможность поправить ячейки до сохранения.

#### Scenario: Пересечение недель
- **WHEN** следующая строка файла начинается раньше конца предыдущей
- **THEN** в предпросмотре предупреждение о пересечении

### Requirement: Действия после предпросмотра
Из предпросмотра SHALL быть три действия: сохранить в текущий план (новая версия активного плана с причиной `import from file` и сверкой версии), создать новый план (карточка из `race` файла JSON или название «Импортированный план»; план становится активным) и отменить (прежний план, ничего не записано).

#### Scenario: Сохранение в план, который успели изменить
- **WHEN** спортсмен сохраняет импорт в текущий план, а план тем временем изменили
- **THEN** предпросмотр закрывается, показывается свежий план и совет загрузить файл ещё раз

#### Scenario: Создание нового плана из JSON
- **WHEN** спортсмен выбирает «Создать новый план» для файла JSON с `race`
- **THEN** создаётся план с названием, датой, целью и стартом из `race`
- **AND** прежний план не меняется

### Requirement: Выгрузка в CSV
Выгрузка CSV SHALL давать файл с заголовком `Нед,Начало,Конец,Акцент,Тип,Пн,Вт,Ср,Чт,Пт,Сб,Вс`, строками через CRLF и BOM UTF-8; ячейки с запятой, кавычкой или переводом строки берутся в кавычки. Имя файла — `plan-<название гонки>-<ГГГГ-ММ-ДД>.csv`. Пустой план MUST NOT выгружаться.

#### Scenario: Выгрузка пустого плана
- **WHEN** спортсмен нажимает «⤓ CSV» у плана без недель
- **THEN** видит «План пуст — нечего выгружать», файл не скачивается

### Requirement: Выгрузка в JSON
Выгрузка JSON SHALL давать `{"format": "running-tracker-plan", "version": 1, "race": {...}, "weeks": [...]}` с карточкой гонки активного плана и всеми полями недель. Такой файл MUST загружаться обратно без потерь недель и карточки.

#### Scenario: Выгрузить и загрузить обратно
- **WHEN** спортсмен выгружает план в JSON и загружает файл как новый план
- **THEN** недели и карточка гонки нового плана совпадают с исходными

### Requirement: Шаблон плана
Кнопка «Шаблон» SHALL скачивать `plan-template.csv` в формате выгрузки с двумя примерами недель.

#### Scenario: Скачивание шаблона
- **WHEN** спортсмен нажимает «Шаблон»
- **THEN** скачивается CSV с заголовком формата и двумя неделями

### Requirement: Описание формата совпадает с разбором
Документация формата и образцы CSV и JSON SHALL описывать тот же контракт колонок и полей, что принимает загрузка; образец CSV MUST быть без BOM, а образцы CSV и JSON — описывать один и тот же план.

#### Scenario: Образцы в документации
- **WHEN** образец CSV из документации загружают в приложение
- **THEN** он принимается без ошибок
