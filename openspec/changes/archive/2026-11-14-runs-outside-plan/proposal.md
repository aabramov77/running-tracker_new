# Proposal

Issue: [#71 Корректно отражать тренировки в период между планами](https://github.com/aabramov77/running-tracker_new/issues/71)

## Why

Если у спортсмена есть хотя бы один план, новая пробежка без `plan_id` привязывается к **активному** плану, какая бы у неё ни была дата. Пробежка до старта плана, после его окончания или в промежутке между планами попадает в чужой план и искажает его план/факт. Явно сохранить пробежку «без плана» нельзя: в форме такого пункта нет, а пустой `plan_id` сервер понимает как «по умолчанию». Поэтому отвязать пробежку правкой тоже невозможно, и отдельно посмотреть пробежки вне планов тоже нельзя.

## What Changes

- **Привязка по дате вместо «к активному».** Если ключа `plan_id` нет, новая пробежка привязывается к плану, в окна недель которого попадает её дата. Учитываются все датированные планы спортсмена, включая архивные. Если подходят несколько, выигрывает активный, иначе тот, что начался позже. Если дату не покрывает ни один план, а у активного плана диапазон дат неизвестен (недель нет или они не датированы), пробежка уходит в активный план, как раньше. В остальных случаях (между планами, до первого, после последнего) пробежка сохраняется без плана. **BREAKING** (поведение API): раньше такая пробежка всегда уходила в активный план.
- **Явное «без плана» в API.** Ключ `plan_id` со значением `null` (или `""`) значит «без плана». Отсутствие ключа по-прежнему значит «по умолчанию»: для новой пробежки это привязка по дате, при правке прежняя привязка сохраняется. Если правкой отвязать пробежку от плана, создаётся новая версия, история не теряется.
- **Форма пробежки.** В списке «План» появляются пункты «Авто (по дате)» (по умолчанию для новой пробежки) и «Без плана», затем планы. При правке пункта «Авто» нет: выбран план пробежки (архивный — с пометкой «(архив)») или «Без плана», поэтому правка других полей привязку не меняет. После сохранения новой пробежки и после выхода из правки выбор возвращается к «Авто». Список виден всегда, даже если планов нет.
- **Область «Без плана».** В журнал и аналитику добавляется третья кнопка «Без плана» рядом с «Текущий план» и «Все». Она показывает пробежки с `plan_id = null`. Недельный график в этой области скрыт: он строится по неделям активного плана, а пробежки этой области почти все вне их.
- **Метка «Нед N».** Метка в журнале и в последних пробежках на экране «Сегодня» показывается только у пробежек активного плана. Пробежка без плана или из другого плана не получает номер недели активного плана.
- **ИИ-тренер.** «14 последних тренировок» в контексте модели берутся по всем пробежкам, а не только по активному плану, с пометкой плана у каждой («текущий план», «без плана», название другого плана). Иначе после окончания активного плана свежие пробежки, сохранённые без плана, выпали бы из контекста. Разбор пробежки без плана не сравнивает её с днём активного плана: модель получает пометку, что пробежка вне плана.

Вне объёма:
- аналитика по календарным неделям без плана (замена захардкоженного старта `2026-05-10` и «из 13» в метриках);
- массовая перепривязка уже сохранённых пробежек; отдельные пробежки можно перепривязать правкой;
- область «Без плана» в карточке спортсмена у тренера;
- отправка на сервер пробежек, сохранённых без связи (сейчас они остаются только в локальном кэше);
- Android-клиент.

### Modified Capabilities
- `run-log`: меняются требования «Привязка пробежки к плану» (явное «без плана», отвязка правкой) и «Журнал пробежек» (область «Без плана», метка «Нед N» только для пробежек активного плана). Добавляются требования «Привязка по дате», «Недатированный активный план», «Выбор плана в форме пробежки» и «Выбор плана при правке пробежки».
- `training-load`: требование «Сводка и графики аналитики» — область «Без плана»: метрики по пробежкам без плана, недельный график скрыт.
- `ai-coach-dialog`: меняется требование «Свежий контекст на каждый ход» (14 последних пробежек — по всем планам и вне плана). Добавляются «Пометка плана у последних пробежек» и «Разбор пробежки без плана» (пробежка без плана не сравнивается с активным планом).

## Impact

- **Бэкенд:** `storage.py` (`clean_run` кладёт `plan_id` в результат только при наличии ключа; `save_run` применяет умолчание только при отсутствии ключа и принимает ленивое `default_plan(day)`; новая `plan_for_date`; `build_llm_context` — последние пробежки по всем планам; `build_run_focus` — без подстановки активного плана); `api.py` (`h_runs_post` передаёт привязку по дате вместо активного плана); `llm_prompt.py` (пометка плана у последних пробежек, пометка «вне плана» в разборе). `compliance.py` не меняется: из него берутся `week_windows` и `anchor_source`.
- **Фронтенд:** `index.html` (кнопки области, видимость `f-plan-group`, id карточки недельного графика); `app.js` (`renderPlanSelectors`, `saveRun`, `fillRunForm`, `clearRunForm`, `endRunEdit`, `scopedRuns`, `setRunScope`, `renderLog`, `getWeekLabel`, `renderCharts`).
- **Тесты:** `tests/test_storage.py`, `tests/test_routes.py` (привязка по дате, явный `null`, отвязка правкой); `tests/test_entity_history.py` (переход с `default_plan_id` на `default_plan`); `tests/test_ai_coach.py` (последние пробежки и разбор пробежки без плана); `tests/test_frontend_sanity.py` при необходимости.
- **Данные:** миграции нет. Уже сохранённые пробежки сохраняют свою привязку. Формат версии пробежки прежний (`plan_id: null` уже допустим).
- **Офлайн:** пробежка, сохранённая без связи, лежит только в локальном кэше и на сервер не уходит (так и сейчас). С «Авто» у неё нет `plan_id`, поэтому до перезагрузки журнала она видна в области «Без плана».
