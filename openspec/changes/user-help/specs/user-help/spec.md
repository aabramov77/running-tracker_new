# Spec Delta

## Purpose

Встроенная справка для вошедшего пользователя: что умеет приложение, с чего начать и что значат его термины — с входом из меню и из кнопок «ⓘ» рядом с терминами.

## ADDED Requirements

### Requirement: Вкладка «Справка»
Приложение SHALL иметь вкладку «Справка», доступную каждому вошедшему пользователю. Вверху вкладки MUST быть оглавление со ссылками на разделы: «Как начать», «Планы», «Пробежки и старты», «Нагрузка», «ИИ-тренер», «Тренер», «Погода», «Профиль», «Доступ и данные», «Частые вопросы», «Для администратора». Нажатие на пункт оглавления MUST прокручивать вкладку к началу раздела.

#### Scenario: Переход по оглавлению
- **WHEN** пользователь на вкладке «Справка» нажимает «Нагрузка» в оглавлении
- **THEN** вкладка прокручена к разделу «Нагрузка»

### Requirement: Содержание справки
Текст справки SHALL описывать текущее поведение приложения: «Как начать» — профиль, план, первая пробежка; «Планы» — несколько планов, конструктор, план/факт, импорт и экспорт, составление плана с ИИ, область «Без плана», отказ в сохранении устаревшего плана; «Нагрузка» — rTSS, TRIMP, обычная неделя, цена работы; «Профиль» — блоки, пороговый темп, пульсовые зоны. Текст MUST быть сухим, без мотивационных оборотов, с обращением на «вы».

#### Scenario: Составление плана с ИИ в справке
- **WHEN** пользователь открывает раздел «Планы»
- **THEN** в нём описано, как составить план с ИИ-тренером и что план создаётся только по его действию

#### Scenario: Пробежки без плана в справке
- **WHEN** пользователь открывает раздел «Планы»
- **THEN** в нём сказано, куда попадают пробежки, которые не попали ни в один план

### Requirement: Справка не требует сервера
Содержание справки SHALL поставляться вместе с интерфейсом: открытие справки и переходы внутри неё MUST NOT обращаться к API и хранилищу.

#### Scenario: Справка при недоступном API
- **WHEN** API не отвечает, а пользователь открывает «Справку»
- **THEN** все разделы справки видны полностью

### Requirement: Вход в справку
На широком экране кнопка «❓ Справка» SHALL стоять последней в меню вкладок — после «Профиль» и после пунктов по ролям. На телефоне вход MUST быть пунктом «❓ Справка» в «Ещё»; из справки на телефоне MUST вести возврат «‹ Ещё», как из других разделов «Ещё».

#### Scenario: Справка в меню администратора
- **WHEN** администратор открывает приложение на широком экране
- **THEN** «❓ Справка» стоит в меню после «👥 Пользователи»

#### Scenario: Справка на телефоне
- **WHEN** пользователь на телефоне нажимает «Ещё» → «❓ Справка»
- **THEN** открыта вкладка «Справка» с оглавлением вверху

### Requirement: Разделы по ролям
Подраздел «Для тренера» в разделе «Тренер» SHALL быть виден только пользователю, который сам является тренером; раздел «Для администратора» — только администратору. Скрытые части MUST NOT быть видны ни в тексте, ни в оглавлении. Права пользователя справка не меняет: она только описывает возможности.

#### Scenario: Спортсмен с тренером
- **WHEN** спортсмен, у которого есть тренер, но который сам не тренер, открывает «Справку»
- **THEN** раздел «Тренер» виден без подраздела «Для тренера», пункта «Для администратора» в оглавлении нет

#### Scenario: Тренер
- **WHEN** тренер открывает «Справку»
- **THEN** подраздел «Для тренера» виден

### Requirement: Кнопки «ⓘ» у терминов
Рядом с терминами SHALL стоять кнопки «ⓘ», открывающие справку на месте, где термин объяснён: плитки нагрузки по темпу и по пульсу — rTSS и TRIMP, плитка «Цена работы» — цена работы, блок профиля «Порог и МПК» — пороговый темп, блок «Пульс и зоны» — пульсовые зоны, «Что помнит тренер» — память тренера. Кнопка MUST иметь доступное имя, называющее термин.

#### Scenario: Справка о цене работы из аналитики
- **WHEN** пользователь нажимает «ⓘ» у плитки «Цена работы»
- **THEN** открыта «Справка», прокрученная к объяснению цены работы

#### Scenario: Кнопка на экране тренера
- **WHEN** тренер смотрит нагрузку спортсмена и нажимает «ⓘ» у плитки нагрузки по темпу
- **THEN** открыта «Справка» на объяснении rTSS

### Requirement: Возврат из справки
Если справку открыли кнопкой «ⓘ», вверху справки SHALL быть кнопка «‹ Назад», возвращающая на вкладку, откуда её открыли. Если справку открыли из меню или из «Ещё», кнопки «‹ Назад» MUST NOT быть.

#### Scenario: Назад в профиль
- **WHEN** пользователь открыл справку кнопкой «ⓘ» в блоке «Пульс и зоны» и нажал «‹ Назад»
- **THEN** открыта вкладка «Профиль»

#### Scenario: Справка из меню
- **WHEN** пользователь открыл справку кнопкой «❓ Справка» в меню
- **THEN** кнопки «‹ Назад» в справке нет

### Requirement: Подсказка при устаревшем плане
Сообщение об отказе в сохранении плана, который успели изменить, SHALL заканчиваться указанием, где об этом прочитать: «Подробнее — в «❓ Справке», раздел «Планы».». Раздел «Планы» MUST объяснять, почему сохранение отклонено и что делать дальше.

#### Scenario: Правка устаревшего плана
- **WHEN** спортсмен сохраняет неделю, а план за это время изменил тренер
- **THEN** сообщение об отказе называет раздел «Планы» в справке
