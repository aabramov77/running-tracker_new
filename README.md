# Running Tracker

Веб-трекер беговых тренировок: планы подготовки к стартам, журнал пробежек,
импорт данных из Garmin (CSV/FIT), аналитика и рекомендации от внешней LLM.

**Прод:** https://aabramov77.github.io/running-tracker_new/
**Dev-стенд:** Cloudflare Pages (ветка `Dev`, в углу висит бейдж `DEV`)

Приложение многопользовательское: вход через Google, доступ выдаётся
администратором, данные каждого пользователя изолированы.

---

## Возможности

### Планы тренировок
- **Несколько планов на пользователя** — переключатель на вкладке «План»,
  архивирование, отдельная гонка (название, дата, целевое время, старт плана)
  для каждого плана.
- **Календарь на 7 дней** (Пн–Вс) с подсветкой текущей недели и типа недели
  (развивающая / пиковая / подводка / загрузочная / гонка).
- **Конструктор плана** — редактирование недель прямо в таблице, добавление
  недель, версионное сохранение.
- **Импорт плана из файла** — CSV или JSON с предпросмотром, предупреждениями
  и возможностью отменить импорт либо сохранить как новый план.
  Формат описан в [docs/plan-import-format.md](docs/plan-import-format.md),
  образцы — в [docs/samples/](docs/samples/).
- **Экспорт плана** в CSV/JSON + скачивание пустого шаблона.

### Пробежки
- Ручная запись: дата, дистанция, тип тренировки, время, темп, пульс,
  самочувствие, заметки, привязка к плану.
- **Импорт из Garmin CSV** — поддержаны два формата выгрузки (Activities и
  Laps с многострочной шапкой).
- **Импорт из .FIT** — файл разбирается на сервере (`fitparse`), форма
  заполняется автоматически, сохранение — по кнопке. Круги и поминутные
  сэмплы (пульс, темп, высота) хранятся вместе с пробежкой.
- **Детальная карточка пробежки** — графики пульса и темпа по дистанции,
  таблица кругов.
- **Калькулятор** — темп по дистанции и времени и обратно, с переносом
  результата в форму.

### Аналитика и рекомендации
- **Журнал** — хронология пробежек с цветовой индикацией темпа, фильтр по
  плану («текущий план» / «все»).
- **Аналитика** — недельный объём и динамика темпа (Chart.js).
- **Корректировка** — рекомендации от внешней LLM по кнопке. В контекст
  уходят профиль спортсмена, последние 14 дней тренировок, 3 последних
  забега, текущая и следующая недели плана, темпы по кругам и HR-drift.
  Ответ сохраняется версионно.
- **Провайдеры LLM:** Anthropic, OpenAI, Deepseek. Ключ задаёт администратор
  во вкладке «Профиль»; хранится в приватном GCS-объекте и никогда не
  возвращается фронту. Есть дневной лимит запросов на пользователя.

### Старты
Отдельный раздел для результатов забегов: название, дата, дистанция
(4,2 км / 5 км / 10 км / полумарафон / марафон), время.

### Профиль
- Характеристики спортсмена: ФИО, дата рождения, пол, рост, вес, пульс
  максимальный / ПАНО / покоя, МПК, стаж, обычный объём, доступные для
  тренировок дни, травмы и свободные заметки для тренера.
- Вычисляется автоматически: возраст, ИМТ, оценка HRmax по формуле Танаки
  (если максимальный пульс не измерен) и пульсовые зоны.
- **Личные рекорды** подтягиваются из раздела «Старты».
- Профиль — источник контекста для LLM; кнопка «Показать контекст для ИИ»
  показывает ровно тот текст, который уйдёт в модель.
- Хранится версионно: каждое сохранение — новая версия, поэтому история
  веса и пульсовых показателей копится сама.

### Администрирование
- Вкладка «Пользователи» (видна только админу): список зарегистрировавшихся,
  одобрение и отклонение доступа.
- Новый пользователь после входа попадает в статус «на рассмотрении».

## Архитектура

```
GitHub Pages (prod) / Cloudflare Pages (dev)
        index.html + app.js + style.css
                    ↓  REST + Bearer <Google ID token>
        Cloud Run Function (Python 3.11)
             runs-api          runs-api-dev
                    ↓
        GCS: running-tracker-aabramov77 / …-dev
```

### Модули бэкенда

Зависимости идут в одну сторону, циклов нет:

```
config.py       константы: client id, бакет, лимиты
domain.py       словарь домена: дни недели, подписи, дистанции, рекорды
llm_prompt.py   сборка текстового промпта из готового контекста
storage.py      GCS, версии, реестр пользователей, разбор FIT, контекст LLM
api.py          проверка токена, таблица маршрутов, хендлеры
main.py         точка входа Cloud Run Function
```

- Фронтенд — vanilla JS без сборки; выбор API-эндпоинта по hostname.
- Авторизация — Google Identity Services, бэкенд проверяет ID-токен и
  разграничивает данные по `sub` из токена.
- Оффлайн — последние данные кэшируются в `localStorage`.

### Структура данных в GCS

```
users/{sub}/
  runs.json                       журнал пробежек
  races.json                      результаты стартов
  profile.json                    legacy: гонка/цель до #25
  athlete/manifest.json           текущая версия профиля спортсмена
  athlete/v{N}/profile.json       неизменяемая версия профиля
  plans/index.json                реестр планов
  plans/{plan_id}/manifest.json   текущая версия плана
  plans/{plan_id}/v{N}/plan.json  неизменяемая версия недель
  runs/{run_id}/v1/activity.fit   исходный FIT
  runs/{run_id}/v1/details.json   круги и сэмплы
  advice/v{N}/recommendation.json ответы LLM
registry.json                     реестр пользователей и их статусов
config/llm/…                      конфиг и ключ LLM (только админ)
```

**Данные append-only.** Физического удаления и перезаписи нет: правка — это
новая версия объекта плюс переключение `is_current`, удаление — логический
флаг. Подробности и обоснование — в [CLAUDE.md](CLAUDE.md).

## Разработка

```bash
git checkout Dev        # весь код пишется в Dev, в main — только merge
python -m pytest -q     # 190 тестов
```

- Тесты не требуют доступа к GCP: `tests/conftest.py` подменяет
  google-cloud-модули и даёт in-memory `FakeBucket`.
- Хук `.githooks/post-commit` прогоняет pytest после каждого коммита.
- Для ручного глубокого прогона есть субагент `deep-tester`
  (`.claude/agents/deep-tester.md`).
- Фронтенд проверяется статически (баланс скобок, отсутствие
  конфликт-маркеров, cache-buster'ы) — Node в окружении нет.
- При изменении `app.js` / `style.css` поднимайте `?v=N` в `index.html`,
  иначе браузер отдаст старую версию из кэша.

### Деплой

Push в `Dev` → `runs-api-dev` + dev-bucket; push в `main` → `runs-api` +
прод-bucket. Настроено в
[.github/workflows/deploy-cloudrun.yml](.github/workflows/deploy-cloudrun.yml),
аутентификация в GCP — через Workload Identity Federation, без JSON-ключей.
Фронтенд деплоится сам: GitHub Pages из `main`, Cloudflare Pages из `Dev`.

Первоначальная настройка стендов — [docs/env-split-and-cd.md](docs/env-split-and-cd.md),
обоснование выбора инструментов — [docs/env-split-and-cd-decisions.md](docs/env-split-and-cd-decisions.md).
Ручной деплой функции описан в [DEPLOY.md](DEPLOY.md).

### Процесс

Каждая новая фича начинается с issue в
[aabramov77/running-tracker_new](https://github.com/aabramov77/running-tracker_new/issues):
план — в `docs/tickets/N-слаг.md`, коммиты — `feat: #N …`, в теле PR —
`Closes #N`.
